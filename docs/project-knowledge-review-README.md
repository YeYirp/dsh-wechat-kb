# dsh-project-knowledge-review

一个面向中文 DSH 用户的独立本地知识复习插件。

它把文字资料、OCR 图片文字和 ASR 音频转写保存到 DSH 用户目录，在回答知识问题前先检索本地 evidence；严格模式下没有足够证据就明确拒答。插件不需要数据库、向量模型、账号登录或项目 Token，也不会连接、安装或识别任何外部项目。

## 主要能力

- 零配置本地资料库：首次使用时自动创建 v2 存储。
- 一键导入文件：Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）、PDF、图片、音频和常见文本文件直接在本地解析入库；支持多文件、目录和知识库页面拖拽上传。
- Evidence-first 问答：先检索，再根据 evidence 回答；严格模式证据不足即拒答。
- 当前 DSH 模型作答：插件只提供检索 evidence 和系统约束，最终答案仍由当前会话模型生成。
- Markdown 摘要：文字、OCR、ASR 入库后立即生成 Markdown 自动提要；自动过滤导入元数据、RAG 模板和纯时间戳，也可用当前 DSH 模型回写更好的 Markdown 摘要。
- 两级分类：插件自动生成系统初分类，用户可在知识库页面建立并调整自己的二次分类。
- 一级知识库页面：侧栏点击“知识库”进入独立工作区，可查看详细摘要和详细原始内容。
- 安全 Markdown 预览：摘要与原始内容都支持渲染视图和 Markdown 源码视图；不执行 HTML 或脚本。
- 可选 OCR / ASR：默认关闭，只有用户显式开启并配置 DSH 凭据后才访问对应服务。
- 大库友好：轻量 JSONL 索引、单文档原文文件、游标分页和按需原文读取。
- 键盘友好：阅读标签支持方向键切换，抽屉支持 Escape 关闭与焦点返回，并遵循“减少动态效果”偏好。
- v1 自动迁移：旧版整库 JSON 会迁移到 v2，并保留不可覆盖的原始备份。

## 3 分钟快速上手

### 第 1 步：安装插件

```bash
dsh plugin --profile web add dsh-project-knowledge-review
```

安装后重新启动当前 DSH Web 进程并刷新页面。成功后可以看到：

- 侧栏出现“知识库”，位置在“工作区”上方；
- “设置”页面出现“知识复习”；
- 新会话可以使用 `project_knowledge_*` 工具。

第一次使用不需要配置数据库、向量模型、账号或 Token。默认使用“知识库仅供参考”：仍会先检索本地资料，再把知识库证据与模型补充分区展示。

```text
回答策略：reference
资料库：~/.dsh/project-knowledge-review/knowledge.json
OCR：关闭
ASR：关闭
```

### 第 2 步：添加第一份资料

在任意 DSH 对话中直接粘贴你有权使用的文字，例如：

```text
把下面内容加入知识库，标题是“RAG 证据检索入门”，来源是“我的学习笔记”：

RAG 在生成回答前先检索资料库。严格模式只依据证据回答，不写资料标题与来源；
当前知识库没有足够证据时，应明确拒答。
```

插件会调用 `project_knowledge_add_text`，保存原文并返回：

- 资料 ID；
- Markdown 自动提要；
- 摘要来源；
- 系统初分类；
- 本地保存结果。

> 请只导入自己编写、公开授权或已确认有权使用的资料。

### 第 2 步（可选）：直接上传文件

打开侧栏“知识库”，点击右上角“上传资料”，可以一次选择多个 Word、Excel、PPT、PDF、图片、音频或文本文件；也可以把文件直接拖进知识库窗口。文件在 DSH 本机解析，入库后立即生成摘要和分类。

在对话里也可以直接给出路径，例如：

```text
把 D:\资料\差旅管理办法.pdf 和 D:\资料\考勤.docx 加入知识库
```

插件会调用 `project_knowledge_import_file` 解析文件本身，不会把整份原文塞进对话，所以大文件也很快。传入目录时会递归导入其中所有支持的文件（最多 200 个）。

支持格式：

| 类型 | 扩展名 |
| --- | --- |
| Word | `.docx` / `.docm` |
| Excel | `.xlsx` / `.xlsm`（多工作表、日期单元格会保留为可读文本） |
| PowerPoint | `.pptx` / `.pptm` |
| PDF | `.pdf`（文本型；图片型会尝试整页 OCR） |
| 图片 | `.png` / `.jpg` / `.jpeg` / `.webp` / `.gif` / `.bmp`（需要开启 OCR） |
| 音频 | `.mp3` / `.m4a` / `.wav` / `.webm` / `.ogg` / `.flac` / `.aac`（需要开启 ASR） |
| 文本 | `.txt` / `.md` / `.csv` / `.tsv` / `.json` / `.log` / `.xml` / `.html` / `.yaml` / `.ini` |

旧版二进制 `.doc` / `.xls` / `.ppt` 需要先另存为新格式或 PDF。

### 第 3 步：打开知识库阅读

点击侧栏“知识库”，即可搜索资料、按系统分类或个人分类浏览，并在“摘要 / 原始内容”和“渲染 / Markdown 源码”之间切换。

![知识库主阅读界面](docs/images/knowledge-library-overview.png)

界面分为三个按需区域：

- 左侧资料导航：搜索、系统分类、个人分类和资料列表；
- 中间阅读画布：显示完整摘要或按需读取原始内容；
- 右侧资料信息：点击顶部“资料信息”后打开，不会永久挤占正文。

### 第 4 步：建立自己的分类

在左侧点击“新建分类”，创建例如“RAG 入门”“前端复习”等目录。选择一份资料后，打开“资料信息”，即可修改“我的分类”。

![资料信息与个人分类](docs/images/knowledge-library-inspector.png)

系统初分类用于解释插件最初如何归类；“我的分类”由你控制，两者互不覆盖。

### 第 5 步：基于证据复习

回到对话后这样提问：

```text
根据我的知识库解释 RAG 为什么需要引用证据。
```

插件会先调用 `project_knowledge_search`。只有返回了 evidence，当前 DSH 模型才会基于证据回答；回答只给结论和必要计算，不写资料标题、来源或“依据：”小标题。

默认 `reference` 模式会固定区分：

```text
## 知识库内容
基于本地 evidence 的结论；未命中时明确说明知识库没有相关资料。

## 模型补充
当前模型提供的通用知识，不冒充知识库结论。
```

如果你希望资料里没有答案就完全拒答，可以在“设置 → 知识复习”切换为 `strict`。

| 想做什么 | 对 DSH 说什么 |
| --- | --- |

| 批量导入目录 | `把 D:\资料 里所有文件加入知识库` |
| 添加文字资料 | `把下面内容加入知识库，标题是“……”：……` |
| 基于知识库复习 | `根据我的知识库解释……` |
| 查看资料数量 | `我的知识库有多少份资料？` |
| 查看保存位置 | `知识库资料保存在哪里？` |
| 检查项目隔离 | `知识库是否与当前项目共享？` |

查询数量、标题、来源、存储位置或共享范围时，插件调用 `project_knowledge_overview`。作用域始终是当前 DSH 用户的本地资料库，`sharedWithCurrentProject` 始终为 `false`。

## 知识库页面行为

“知识库”入口采用与“任务看板”一致的侧栏按钮规格，并固定放在“工作区”区块之前。知识库打开后，点击任意对话、设置、任务看板、SSH、文件树或其他外部功能都会自动退出知识库，并让原点击继续生效。任务看板或 SSH 打开时点击知识库，也会在同一次点击中退出原面板并进入知识库；从知识库点击任务看板或 SSH 也能单击反向切换。

窄屏下，资料导航和资料信息会变成抽屉，正文使用完整可用宽度。阅读标签支持方向键切换，抽屉支持 Escape 关闭与焦点返回。

页面只借鉴主流文档与知识产品的信息架构，不复制第三方品牌或素材。

## 回答策略

### `strict`

- 知识问题必须先检索。
- 只有 `answerStatus=ANSWERED` 且 evidence 非空时才能回答。
- 只陈述 evidence 支持的结论。
- 没有证据时必须明确说明：`当前知识库中没有足够证据，不能回答`。
- 不使用模型记忆补齐知识结论。

### `reference`（默认，界面显示“知识库仅供参考”）

- 仍先检索知识库。
- 允许当前模型补充通用知识。
- 必须明确区分“知识库证据”和“模型补充”。

可以在“设置 → 知识复习”中切换策略。

## 本地 v2 存储

默认路径：

```text
~/.dsh/project-knowledge-review/knowledge.json
```

同目录还会出现：

```text
knowledge.json                         # 常数大小 manifest
knowledge.json.index.jsonl             # 元数据与检索 token 轻量索引
knowledge.json.documents/              # 每份资料一个 JSON 原文文件
knowledge.json.categories.json         # 用户二次分类
knowledge.json.locks/                   # 多进程 ticket 锁
knowledge.json.journal.json             # 中断恢复日志，仅写入期间存在
knowledge.json.v1.backup*.json          # v1 迁移备份（如有）
```

v2 的设计目标：

- 列表和概览不加载全量原文。
- 原文按单条 ID 哈希文件名直接定位。
- 写入和元数据更新使用跨进程 ticket 锁。
- journal 中断恢复保持清单、JSONL 索引和单条原文一致。
- 单次预览、请求体和媒体文件均有大小限制。

## OCR 与 ASR

OCR / ASR 默认关闭。启用步骤：

1. 打开“设置 → 知识复习”。
2. 开启对应服务。
3. 配置 Base URL 与模型名称。
4. 将 API Key 保存到 DSH 凭据库。

安全边界：

- 图片和音频既可以来自公开 HTTP(S) URL，也可以来自本地上传或本地路径。
- 本机文件默认只在 DSH 本机解析和保存；只有开启 OCR / ASR 时，图片或音频才会发送给设置中配置的模型服务。
- 拒绝 URL 用户信息、非 HTTP(S) 协议、本机地址和私有网络地址。
- API Key 不写入插件设置 JSON，也不会回显。
- 插件不自动处理视频网页分享页；请提供字幕文字或公开音频直链。

PDF 文本提取使用随插件安装的 `unpdf`（PDF.js）；不需要额外安装系统软件。

## 图片资料

- 纯图片（.jpg/.png/.bmp/.tif 等）导入时先 OCR；OCR 失败或未开启也**不丢图**：原图照样压缩保存，正文写一句“图片资料：文件名（OCR 未识别出文字，原图已保留）”占位。
- .docx/.xlsx/.pptx 会从 zip 的 `word/media/`、`xl/media/`、`ppt/media/` 保留内嵌图片，并对这些图复用同一套 OCR，把图内文字以 `【图内文字】` 标记拼进正文。
- 文字型 PDF 会用 PDF.js 抽取页面图片；内嵌图片会走 OCR，图内文字拼到对应页正文后面，表格图/铭牌图因此能被 BM25 命中。文字层为空时也不再直接拒绝：会把整页图抽出来 OCR，OCR 出字就按 `【图内文字】` 入库；整页 OCR 也认不出字才报错。OCR 失败只记日志，不影响其他页/文字层。
- 图片长边压到 1024 像素、JPEG 质量 75；用 Windows 自带 System.Drawing，不新增 npm 依赖。
- 资料 JSON 只存 `images: [{ path, mediaType, page?, caption? }]`，不存 base64。老库没有 `images` 字段时按空数组处理。
- 图片不参与 BM25 打分；检索仍看正文文字，命中后 `evidences[].images` 会带出图片元数据，微信桥接可据此把图交给模型（只给模型看，微信出站仍然只发文字）。

## 检索打分与命中阈值

- 打分是 BM25 一族：`score = Σ IDF(词) × 词频饱和系数`，长度归一使用资料自身长度，
  `k1 = 1.2`、`b = 0.75`，IDF 带 `+1` 平滑。问题侧词数不再出现在分母里，
  所以口语越长越难命中的问题已修复。
- 中文按汉字二元词（bigram）建索引；`个/这/那/我/你/会/样/儿/了/吗/呢/吧/啊/的` 等虚词不参与打分；
  `怎么样 / 怎么办 / 咋办 / 是不是 / 有没有` 等问句壳在查库前先去掉。
- 数字与中文数量词在提问侧和资料侧共用同一个纯函数归一：`三次 ↔ 3次`、`三十 ↔ 30`、
  `半小时 ↔ 30分钟`、`半天 ↔ 0.5天`、`一周 ↔ 7天`。
- 第一次未命中时用插件目录里的本地同义词表再查一次，全程不联网、不调模型。
- 有证据但只能回答一部分时，先答能确定的部分，再用一句自然的话说明哪部分资料没有；只有完全无证据才拒答。表格式条款（如“职级分类如下”后接表格）会把表格行补成第二条证据。同一节下 `1、2、3、` 编号的相邻条款会合并给模型；问题里带具体次数/数字时不自动扩张，保持证据短。
- 回答要尽量全面：证据里与问题相关的条件、例外、后果都要覆盖；拿不准某一条是否适用时，用一句自然的补充说明，不要直接省略（除非用户明确只要简短答案或只问某一点）。
- 微信/回复里不写“依据：”“根据：”这类小标题，也不写文件名、章节号或检索过程。
- 只靠单字或“办法/规定/流程/需要”这类泛化词不能单独构成命中；领域词（发票、迟到、罚款等）可以。
- 候选先多召回（至少 24 条），再在本地按标题命中、数字/日期是否对得上、条款去重做一次精排，
  最后只把 `evidenceCount` 条交给模型；每条按条款/句子边界截到 `evidenceMaxChars`。

阈值 `1.4` 由 `lib/retrieval.test.js` 的样本标定（旧微信层写死的 `0.5` 已废弃）：

| 问题 | 判定 | 改造后分数 |
| --- | --- | --- |
| 这个月我迟到了三次，会怎么样 | 命中（考勤管理办法） | 2.949 |
| 迟到三次会怎么样 | 命中 | 2.949 |
| 迟到三十分钟以内怎么处罚 | 命中 | 4.290 |
| 月累计三次以上除了罚款还有什么 | 命中 | 5.094 |
| 旷工半天怎么算 | 命中 | 3.218 |
| 上下班忘打卡第一次怎么处理 | 命中 | 7.508 |
| 发票原件要留存多久 | 命中 | 10.140 |
| 发票丢了怎么办 | 命中（最低正样本） | 1.690 |
| 今天天气怎么样 | 未命中 | 0 |
| 这个办法怎么样 | 未命中（只有泛化词） | 0 |
| 今天迟到了天气怎么样 | 未命中（只沾一个词） | 0 |

验收固定资料集（考勤规章 + 发票规章）上，同一句「这个月我迟到了三次，会怎么样」的
证据文本从改造前的 **179 字**（考勤 135 字 + 发票 29 字 + 标题）降到 **91 字**，
是旧基线的 **50.8%**。

在真实用户库（5 份资料）上同一句的对照：改造前召回 4 条、证据文本 **2540 字**，
排第一的是差旅办法（旧分 0.615，考勤 0.385）；改造后只召回 1 条考勤办法、
证据文本 **89 字**（旧基线的 **3.5%**，新分 4.094）。旧阈值 `0.5` 会把这条真正相关的
考勤资料判成未命中，而把 0.615 的差旅资料放进来，这正是本次修复的问题。

旧打分下的三个关键样本：详细提问 `0.385`、短提问 `0.500`、天气 `0.167`；
新打分分别为 `2.949 / 2.949 / 0`，阈值 `1.4`。

## 设置项

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关闭后工具和提示词保持静默 |
| `answerPolicy` | `reference` | 默认“知识库仅供参考”；可切换为严格 `strict` |
| `localStorePath` | `~/.dsh/project-knowledge-review/knowledge.json` | 插件自己的本地资料库 |
| `projectName` | `我的知识库` | 用户可见名称；仅是命名，不是外部项目 |
| `evidenceCount` | `3` | 每次问答最多交给模型的资料条数（1–10） |
| `evidenceMaxChars` | `320` | 每条证据按条款/句子边界截取的最大字数（80–1200） |
| `requestTimeoutMs` | `120000` | OCR / ASR 请求超时 |
| `ocrEnabled` | `false` | 是否启用 OCR |
| `ocrBaseUrl` | DashScope OpenAI 兼容地址 | OCR 服务地址 |
| `ocrModel` | `qwen-vl-ocr` | OCR 模型 |
| `ocrApiKeyEnv` | `DSH_KNOWLEDGE_OCR_API_KEY` | DSH 凭据引用名 |
| `asrEnabled` | `false` | 是否启用 ASR |
| `asrBaseUrl` | OpenAI API 地址 | ASR 服务地址 |
| `asrModel` | `whisper-1` | ASR 模型 |
| `asrApiKeyEnv` | `DSH_KNOWLEDGE_ASR_API_KEY` | DSH 凭据引用名 |

## 隐私与发布边界

- 插件独立发布、独立运行、独立存储。
- 插件没有项目 URL、项目 API Key、配对码、能力文件或项目安装逻辑。
- 插件不会主动向外部项目同步资料。
- 插件摘要和分类只属于插件本地库。
- 如果个人项目希望使用这些资料，应由该项目在自己的服务端实现主动、只读同步；这不属于本插件的公共能力。

## 开发

```bash
npm install
npm test
npm run typecheck
npm pack --dry-run
```

`npm test` 会先清理并重建 `lib/`，防止删除过的旧功能残留在发布包中。
